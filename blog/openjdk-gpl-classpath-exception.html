OpenJDK is GPL-licensed. So why can you ship it inside closed-source software?

By HiroCheck · Published 2026-08-17

Almost all of OpenJDK is licensed under GPLv2 — plus one addition that changes everything: the Classpath Exception. The full SPDX expression is GPL-2.0-only WITH Classpath-exception-2.0 (or the -or-later variant). Several core Java EE / Jakarta libraries that show up as transitive dependencies in JVM-based projects — for example javax.activation and javax.el — declare the same license.

Plain GPL-2.0 is copyleft: link it into your own program, and (under the usual reading) your program's source may need to be shared under GPL too. That's why GPL/AGPL dependencies get flagged by every license scanner, license-radar included. But WITH Classpath-exception-2.0 isn't decoration — it's an operative clause. Per OpenJDK's own license page, the exception exists specifically "to permit you to use, modify and redistribute [OpenJDK's code] in combination with other independent modules" — including proprietary ones — "without such combination causing the resulting work to be covered by the GNU General Public License." That's the entire reason companies can embed OpenJDK inside closed-source products without open-sourcing their own code, something plain GPL would not allow.

Why "WITH" breaks scanners built for plain GPL

SPDX expressions use WITH as a distinct operator from AND/OR: license WITH exception means "this exact license, modified by this exact exception" — not a choice between two licenses. A scanner that only tokenizes on AND/OR and then does a plain string/id lookup on whatever's left will either fail to match GPL-2.0-only WITH Classpath-exception-2.0 at all, or — worse — strip the WITH Classpath-exception-2.0 part and classify the dependency as plain, unmodified GPL. The first just means a missed row; the second means a false compliance alarm on a dependency that was specifically license-exempted for this exact use case.

Either failure mode defeats the entire point of running a scanner: a missed row means the exemption never gets recorded, and a false GPL flag means someone has to burn review time re-proving what the SPDX expression already said. The fix isn't a smarter guess — it's refusing to guess at all when the operator can't be resolved with certainty. That's the design choice license-radar makes.

How license-radar handles it

license-radar resolves compound SPDX expressions like A OR B and A AND B by their actual operator semantics rather than string-matching. For WITH, it deliberately does the opposite of guessing: since it does not model license exceptions, any expression containing WITH is refused outright and reported as unknown rather than silently collapsed to the base license. Checked directly against the library:

>>> from license_radar.classify import classify_expression
>>> classify_expression("GPL-2.0-only WITH Classpath-exception-2.0")
'unknown'

That "unknown" is not a bug — it's the honest answer. Silently reporting this as strong-copyleft would raise a false alarm on a dependency the upstream project explicitly cleared for proprietary linking. Silently reporting it as permissive would be worse: guessing away a real exception clause that a scanner never actually verified. Either guess could be wrong, so license-radar surfaces it for manual review instead — the same policy it applies to any SPDX expression it cannot fully and unambiguously resolve.

What to actually do about it

If a dependency scan flags something as GPL-2.0 WITH Classpath-exception-2.0 (or unknown and the raw license string contains "Classpath"), that's very likely fine to link into closed-source code the same way OpenJDK itself is — but confirm it by reading the actual license text bundled with the dependency rather than trusting the tag alone (dependency metadata is self-reported and occasionally wrong). This is general technical information, not legal advice; for anything commercially significant, a quick read of OpenJDK's own explanation of the exception is a good starting point, and counsel review is warranted for high-stakes cases.
