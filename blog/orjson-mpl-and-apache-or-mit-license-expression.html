PyPI lists orjson under three OSI licenses. AND makes sure only one of them actually binds

By HiroCheck · Published 2026-09-07

orjson — a fast JSON library for Python, widely pulled in as a drop-in replacement for the standard library's json module — carries three separate License :: trove classifiers on PyPI, listed with no ordering or structure between them:

curl -s https://pypi.org/pypi/orjson/json | python3 -c \
  "import json,sys; d=json.load(sys.stdin)['info']; \
   print([c for c in d['classifiers'] if 'License' in c])"
# -> ['License :: OSI Approved :: Apache Software License',
#     'License :: OSI Approved :: MIT License',
#     'License :: OSI Approved :: Mozilla Public License 2.0 (MPL 2.0)']

A scanner that only reads classifiers — the flat list, with no way to express how the three relate — has to guess which one is "the" license. The actual answer isn't a guess. orjson's structured license_expression field, present in the same PyPI JSON response, spells out the relationship directly:

print(d['license_expression'])
# -> MPL-2.0 AND (Apache-2.0 OR MIT)

What the nesting actually says

Read outside-in: the whole package is under MPL-2.0 AND a separate (Apache-2.0 OR MIT) grant. The parenthesized OR is real — some part of orjson's code is dual-licensed, and a licensee gets to pick whichever of Apache-2.0 or MIT is more convenient for that part. But the AND wrapped around it is not optional: satisfying the OR-branch does not excuse you from the MPL-2.0 terms that apply to the rest of the codebase. You don't get to point at the OR, pick MIT, and walk away — MPL-2.0's file-level copyleft obligations still bind regardless of which side of the OR you'd have chosen.

That makes the three flat classifiers actively misleading on their own. Nothing in the classifier list distinguishes "you may pick any of these three" from "one of these plus a choice of the other two." A tool — or a person — that just sees "Apache, MIT, MPL, pick whichever looks best" has no way to recover the actual structure from that list alone.

What a classifier-only reading would get wrong

The classifiers list carries no order guarantee, but even taking them at face value in the order PyPI returns them (Apache first) shows the failure mode directly:

>>> from license_radar.classify import classify_license, classify_expression
>>> classify_license("Apache-2.0")   # naive: first classifier in the list
'permissive'
>>> classify_expression("MPL-2.0 AND (Apache-2.0 OR MIT)")   # actual expression
'weak-copyleft'

Picking the first recognizable classifier calls orjson permissive. Resolving the actual expression puts it at weak-copyleft — the same tier as tqdm's MPL-2.0 AND MIT (covered in an earlier post), but arrived at through a nested expression rather than a flat one. The gap between those two answers is exactly the MPL-2.0 file-level obligation that a permissive verdict silently drops.

How license-radar resolves the nesting

license-radar's expression resolver (spdx_expr.py) implements SPDX operator precedence directly — AND binds tighter than OR, parentheses group as usual, AND takes the most restrictive operand and OR the least — rather than matching on any single token in the string:

>>> from license_radar.spdx_expr import tier_of_expression
>>> tier_of_expression("MPL-2.0 AND (Apache-2.0 OR MIT)")
'weak-copyleft'
>>> tier_of_expression("Apache-2.0 AND MIT")   # no OR branch, for contrast
'permissive'

This exact expression is the resolver's own canonical example — the module-level docstring in spdx_expr.py cites orjson's MPL-2.0 AND (Apache-2.0 OR MIT) by name as the case that motivated supporting parenthesized, mixed AND/OR expressions rather than only flat lists. license-radar's static package DB pins the same package as a regression fixture with the same reasoning recorded inline ("orjson": "MPL-2.0", # "MPL-2.0 AND (Apache-2.0 OR MIT)"; MPL term applies), and the test suite asserts both classify_expression("MPL-2.0 AND (Apache-2.0 OR MIT)") == "weak-copyleft" directly and ("pypi", "orjson") resolving to weak-copyleft through a full scan fixture.
