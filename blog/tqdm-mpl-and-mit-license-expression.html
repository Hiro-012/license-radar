tqdm shows up as MIT everywhere. Its own LICENCE file says MPL-2.0 AND MIT

By HiroCheck · Published 2026-09-02

tqdm — the progress-bar library with over 8.3 billion PyPI downloads — is one of the most widely assumed-permissive dependencies in the Python ecosystem. Ask most tooling and it will say "MIT." Check what tqdm itself actually declares, and the answer is a compound expression:

curl -s https://pypi.org/pypi/tqdm/json | python3 -c \
  "import json,sys; print(json.load(sys.stdin)['info']['license'])"
# -> MPL-2.0 AND MIT

tqdm's PyPI metadata also carries zero License :: trove classifiers — the field many older, classifier-only scanners fall back on when there's no structured license expression to parse. For tqdm, that fallback field is simply empty.

Where the split actually comes from

tqdm's own LICENCE file (in the project's GitHub repo) spells out the split directly — it isn't a registry-metadata quirk:

* files: *
  MPL-2.0 2015-2026 (c) Casper da Costa-Luis
* files: tqdm/_tqdm.py README.rst .gitignore
  MIT 2013 (c) Noam Yorav-Raphael, original author.

In other words: the default license for the codebase, covering essentially every file added since the current maintainer took over in 2015, is MPL-2.0 — a weak-copyleft license. Only a small set of files from the original 2013 author stayed under the original MIT grant. A user opened a GitHub issue asking about exactly this, pointing out that because the MPL-2.0 maintainer's changes now touch nearly the whole codebase, tqdm is arguably "de facto" MPL-2.0 rather than a package you can treat as MIT with an asterisk.

Why "AND" isn't a rounding error

Distinct from an OR expression (the licensee may pick either license — see packaging's Apache-2.0 OR BSD-2-Clause, or cryptography's similar dual grant), an AND means both sets of terms apply at once. You don't get to choose the more permissive half and ignore the rest. For tqdm specifically, that means MPL-2.0's file-level copyleft — modifications to MPL-covered files must themselves stay under MPL-2.0 and have their source made available — binds on top of the MIT terms for the small carved-out set of legacy files. Picking "MIT" and moving on skips a real obligation for anyone modifying and redistributing most of tqdm's actual source.

How license-radar handles this

license-radar resolves compound SPDX expressions by their actual operator semantics rather than a name lookup:

>>> from license_radar.classify import classify_expression
>>> classify_expression("MPL-2.0 AND MIT")
'weak-copyleft'
>>> classify_expression("MIT")
'permissive'

AND resolves to the most restrictive operand (here, MPL-2.0's weak-copyleft tier) rather than the least — the opposite of how OR is resolved. Getting this backwards, or simply matching on the first recognizable token in a string like "MPL-2.0 AND MIT", is exactly the kind of mistake that silently downgrades a real obligation to "looks fine, it says MIT in there somewhere."

license-radar's own test suite pins this exact package as a regression fixture rather than leaving it to a general rule: ("pypi", "tqdm") is asserted to resolve to weak-copyleft, alongside direct unit tests of tier_of_expression("MPL-2.0 AND MIT").
